# Plan: Recipe Data Cleanup and Nutrition Sync

## Task Description
Оновити дані рецептів у `recipes.json` на основі фінальних даних БЖУ з `КнигаРецептівUpdated.txt`. Головні завдання:
1. Синхронізувати харчову цінність (БЖУ) з останнього текстового файлу
2. Виправити змішування інгредієнтів та інструкцій (ingredients пішли у how_to_cook і навпаки)
3. Оновити відсутні деталі рецептів

**Паралелізм**: Кожна сторінка/рецепт незалежні один від одного, тому можна використовувати subagents для обробки кожного рецепта окремо.

## Objective
По завершенню цього плану:
- Усі 65 рецептів матимуть коректні БЖУ з `КнигаРецептівUpdated.txt`
- Поле `ingredients` міститиме тільки інгредієнти
- Поле `how_to_cook` міститиме тільки інструкції приготування
- UI правильно відображатиме структуровані дані

## Problem Statement
При початковому парсингу рецептів виникли проблеми зі структурою даних:

### Проблема 1: Інгредієнти у полі how_to_cook
Приклад (рецепт "Ліниві вареники"):
```json
"how_to_cook": [
  "Прикрашаємо:",      // <-- Заголовок секції
  "15г йогурт 1,5%",   // <-- ЦЕ ІНГРЕДІЄНТ!
  "10г мигдалю",       // <-- ЦЕ ІНГРЕДІЄНТ!
  "5г гарбузовим насінням"
]
```

### Проблема 2: Інструкції у полі ingredients
Приклад (рецепт "Поєднання класики"):
```json
"ingredients": [
  "150г філе куряче",
  "70г цільнозернові макарони",
  "Філе маринувати у спеціях і на грильку",  // <-- ЦЕ ІНСТРУКЦІЯ!
  "Броколі варити 3хв"                        // <-- ЦЕ ІНСТРУКЦІЯ!
]
```

### Проблема 3: Розбіжності у кількостях
Приклад: Десерт "Шоколадний десерт" - JSON має 200г хурми, TXT має 230г хурми.

## Solution Approach
1. **Парсер для txt файлу**: Використати/модифікувати існуючий `add_nutrition_data.py` для повного парсингу
2. **Паралельна обробка**: Розділити роботу по категоріях (сніданки, обіди, десерти) з використанням subagents
3. **Валідація**: Створити скрипт для автоматичної перевірки структури даних

### 7. Створити скрипт валідації
- Створити `scripts/validate-recipes.py`:
  ```python
  def validate_recipe(recipe):
      errors = []
      # 1. Перевірка що ingredients не містить інструкцій
      for ing in recipe['ingredients']:
          if is_instruction(ing):
              errors.append(f"Instruction in ingredients: {ing}")

      # 2. Перевірка що how_to_cook не містить інгредієнтів
      for step in recipe['how_to_cook']:
          if is_ingredient(step) and not is_section_header(step):
              errors.append(f"Ingredient in how_to_cook: {step}")

      # 3. Перевірка наявності nutrition
      if not recipe.get('nutrition'):
          errors.append("Missing nutrition data")

      return errors
  ```

## Notes

### Паралелізм з Subagents
Для ефективної обробки можна запустити 3 subagents паралельно:
1. `build-agent` для обробки сніданків (20 рецептів)
2. `build-agent` для обробки обідів/вечер (25 рецептів)
3. `build-agent` для обробки десертів (20 рецептів)

Кожен agent отримує:
- Відповідну секцію з txt файлу
- Поточні дані з recipes.json для своєї категорії
- Інструкції по класифікації контенту

### Залежності
Скрипти використовують тільки стандартну бібліотеку Python (json, re, pathlib), нові пакети не потрібні.

### Edge Cases
- Рецепти з форматуванням "•" (десерти 11, 12) - видалити маркери
- Рецепти з числовими роздільниками "1", "2" (сніданок 3) - перетворити на секції
- Рецепти без інструкцій (порожній how_to_cook) - це нормально, UI показує "Швидкий рецепт"
